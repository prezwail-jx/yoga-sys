**Feature Branch**: `002-member-card-core`

## Clarifications

### Session 2026-02-25

- Q: 会员“删除”采用何种语义？ → A: 软删除（禁用/归档），不物理删除历史数据。
- Q: 多张可用卡并存时核销优先顺序？ → A: 先到期先扣（同到期按更早开卡时间优先）。
- Q: 冻结期间有效期如何计算？ → A: 冻结期间暂停计时，解冻后按冻结天数顺延到期日。
- Q: 哪些角色可跨会员查询完整记录？ → A: 仅管理员可跨会员查询；教练仅查看本人相关；会员仅查看本人。
- Q: 过期提醒触发阈值是多少？ → A: 到期前 7 天开始提醒。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 管理员维护会员与卡项基础资料 (Priority: P1)

作为管理员，我可以新增、编辑、查询、删除会员资料并维护会员状态，同时配置卡项类型与核心字段，
以便后续购卡、核销、有效期管理有一致且可执行的业务基础。

**Why this priority**: 会员与卡项主数据是全流程基础，没有该能力无法开展任何后续交易与核销。

**Independent Test**: 仅实现本故事即可完成会员档案全生命周期与卡项规则配置，且可被业务人员独立使用。

**Acceptance Scenarios**:

1. **US1-AS1 Normal**: **Given** 管理员已登录且具备会员管理权限，**When** 新增会员并保存姓名、手机号、入会日期，**Then** 系统成功创建会员并在列表可检索。
2. **US1-AS2 Normal**: **Given** 管理员已登录且具备卡项管理权限，**When** 新建“次数卡”并设置售价、总次数、开卡方式、适用课程、缺勤扣次与取消返还规则，**Then** 卡项状态为可用并可用于购卡。
3. **US1-AS3 Boundary**: **Given** 会员状态由“正常”切换为“禁用”，**When** 再尝试为该会员执行新增预约相关动作，**Then** 系统阻止并提示会员状态不允许预约。
4. **US1-AS4 Exception**: **Given** 教练角色登录，**When** 尝试编辑非本人所属会员资料或卡项核心规则，**Then** 系统拒绝操作并记录越权审计日志。

---

### User Story 2 - 管理员办理卡项交易与状态变更 (Priority: P2)

作为管理员，我可以为会员办理购卡、续费、补卡、退款，以及冻结、延期、解冻和过期提醒管理，
以保证会员卡项权益和账务状态准确可追踪。

**Why this priority**: 交易与状态变更直接影响会员权益和经营现金流，是核心运营流程。

**Independent Test**: 仅实现本故事即可独立完成卡项交易闭环与状态管理，不依赖排课与消息模块。

**Acceptance Scenarios**:

1. **US2-AS1 Normal**: **Given** 会员具备可办理条件，**When** 管理员执行购卡或续费，**Then** 系统生成交易记录并更新卡项剩余次数、有效期与开卡状态。
2. **US2-AS2 Normal**: **Given** 会员卡项处于可冻结状态，**When** 管理员执行冻结后再执行解冻，**Then** 系统按规则更新状态并保留完整操作轨迹。
3. **US2-AS3 Boundary**: **Given** 卡项即将到期（例如剩余 1 天），**When** 到达提醒触发条件，**Then** 系统将该卡项标记为“即将到期”并在会员视图可见提醒标识。
4. **US2-AS4 Exception**: **Given** 同一笔交易已完成退款，**When** 管理员再次提交同一退款请求，**Then** 系统执行幂等处理，返回已处理结果且不重复变更余额或次数。

---

### User Story 3 - 运营人员查询会员业务记录并核对核销链路 (Priority: P3)

作为管理员或被授权运营人员，我可以按会员查看购卡、续费、退款、约课、签到、缺勤等记录，
并核对“预约预扣 -> 签到实扣 -> 取消返还”全过程，确保业务可审计、可追溯。

**Why this priority**: 记录查询与核销追溯支撑客服答疑、纠纷处理和内部审计，但在业务价值上次于交易办理。

**Independent Test**: 仅实现本故事即可完成会员时间线查询与核销链路核对，不依赖报表模块。

**Acceptance Scenarios**:

1. **US3-AS1 Normal**: **Given** 会员已存在多笔购卡与约课数据，**When** 运营人员进入会员记录页，**Then** 可按时间线查看购卡、续费、退款、约课、签到、缺勤记录。
2. **US3-AS2 Normal**: **Given** 一笔预约后已签到，**When** 查询核销记录，**Then** 能看到预扣与实扣的关联关系及操作人、时间、对象信息。
3. **US3-AS3 Boundary**: **Given** 会员当日发生多次状态变化（预约、取消、再次预约），**When** 查询时间线，**Then** 记录顺序与事件结果保持一致且不丢失中间事件。
4. **US3-AS4 Exception**: **Given** 会员尝试读取其他会员记录，**When** 发起查询请求，**Then** 系统拒绝并记录越权访问日志。

---

### Edge Cases

- 同一会员在短时间内重复提交退款、冻结、解冻请求时，系统必须保持幂等，不重复扣减或返还权益。
- 会员存在多张可用卡项时，系统需按“先到期先扣（同到期按更早开卡时间优先）”选择核销目标卡项，并记录选择依据以便审计。
- 卡项在“冻结”与“到期”状态交叉发生时，系统需给出唯一最终状态并可追溯状态迁移路径。
- 冻结结束后卡项到期日必须按冻结天数顺延，且顺延结果可被审计追溯。
- 已过期或无可用次数的卡项即使存在历史预约记录，也不得用于新的预约预扣。

## Constitution Alignment *(mandatory)*

- **CA-001 Role Isolation**: 本功能定义管理员/教练/会员三类角色边界；所有写操作与敏感读操作均要求服务端鉴权与资源归属校验。
- **CA-002 Write-off Model**: 核销统一采用 `预约预扣 -> 签到实扣 -> 取消返还`，适用于团课与私教相关记录口径。
- **CA-003 Concurrency & Idempotency**: 购卡、退款、冻结/解冻、核销扣返均要求并发安全与幂等结果，避免重复变更。
- **CA-004 Traceability**: 所有关键事件必须保留可查询日志，支持按会员与时间线追溯。
- **CA-005 Acceptance Mapping**: 本文需求与验收场景映射到 PRD 条款，并覆盖正常/边界/异常流。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持管理员新增、编辑、查询、删除会员资料，并维护会员状态（正常、停卡、到期、禁用）；其中“删除” MUST 为软删除，不得物理删除历史交易与核销记录。
- **FR-002**: 系统 MUST 支持维护卡项类型（期限卡、次数卡、私教卡、体验卡）及其核心字段（售价、总次数、有效期、开卡方式、适用课程、缺勤扣次、取消返还）。
- **FR-003**: 系统 MUST 支持管理员办理购卡、续费、补卡、退款，并生成可追溯的交易记录。
- **FR-004**: 系统 MUST 支持卡项冻结、延期、解冻，并在状态变更后更新会员可用权益。
- **FR-005**: 系统 MUST 提供过期识别与到期提醒标识，提醒阈值 MUST 为到期前 7 天，使运营可识别即将到期与已到期卡项。
- **FR-006**: 系统 MUST 统一执行核销规则 `预约预扣 -> 签到实扣 -> 取消返还`，并确保重复请求结果幂等；多卡并存时 MUST 按先到期先扣（同到期按更早开卡时间优先）执行核销。
- **FR-007**: 系统 MUST 支持会员记录查询，至少包含购卡、续费、退款、约课、签到、缺勤，并可按会员时间线查看。
- **FR-008**: 系统 MUST 在服务端执行角色鉴权与资源归属校验，禁止越权读写会员和卡项数据；跨会员记录查询权限 MUST 仅授予管理员。
- **FR-009**: 系统 MUST 为关键操作记录审计日志，至少包括操作人、操作时间、操作对象、变更前后状态与结果。
- **FR-010**: 系统 MUST 在并发或重复提交场景下避免重复扣次、重复退款、重复状态切换。
- **FR-011**: 对于到期或无可用卡项会员，系统 MUST 拒绝新的预约预扣请求。
- **FR-012**: 系统 MUST 在卡项冻结期间暂停有效期计时，并在解冻后按冻结天数顺延到期日。

### Key Entities *(include if feature involves data)*

- **会员（Member）**: 代表学员主体，包含基础档案信息、状态、关联卡项集合及软删除标识。
- **卡项定义（Card Product）**: 代表可售卖卡种模板，包含卡项类型与核心规则字段。
- **会员卡实例（Member Card）**: 代表会员实际持有卡项，包含开卡状态、有效期、剩余次数、冻结信息。
- **交易记录（Card Transaction）**: 代表购卡、续费、补卡、退款等权益与资金变更事件。
- **核销事件（Write-off Event）**: 代表预约预扣、签到实扣、取消返还的链路事件与结果，包含核销目标卡选择依据。
- **操作审计日志（Audit Log）**: 代表关键动作留痕，支持按会员、角色和时间线追溯。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 业务人员对会员执行新增、编辑、状态更新的成功完成率达到 99% 及以上。
- **SC-002**: 购卡、续费、补卡、退款、冻结、解冻等操作在首次提交后 3 分钟内可被完整追溯到记录明细。
- **SC-003**: 在重复提交或并发提交场景下，100% 不发生重复扣次、重复退款或重复状态变更。
- **SC-004**: 抽样核对 100 笔核销链路时，`预约预扣 -> 签到实扣 -> 取消返还` 事件关联一致率达到 100%。
- **SC-005**: 会员记录查询可在单个页面完成时间线核查，业务核查耗时较现有人工台账方式降低 50% 以上。

## Out of Scope

- 团课排课与课表编辑（包括每周课表可视化与调课能力）。
- 私教时段发布与教练端空闲时间管理。
- 报表统计与导出能力。
- 消息通知能力（短信、微信服务通知、课前提醒）。

## Assumptions

- 本 feature 仅覆盖“会员与卡项核心”域，不改变现有登录认证方式。
- “过期提醒”在本阶段以系统内可见提醒标识为验收目标，不包含外部推送渠道。
- 会员记录查询默认按会员维度与时间线展示，不新增跨门店经营分析视图。
