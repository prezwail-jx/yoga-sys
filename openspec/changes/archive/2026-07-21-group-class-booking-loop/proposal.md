## Why

系统已经具备会员、卡项、交易、核销和审计基础能力，但团课课表与预约仍使用 Mock 数据，无法承接 PRD 中最核心的约课运营流程。现在需要将现有卡项核销能力接入真实课程和预约业务，形成可独立运营、验收和追溯的团课闭环。

## What Changes

- 新增课程、教室和教练基础资料，供排课与卡项适用课程校验使用。
- 新增真实团课课次，支持周视图查询、创建编辑、发布、暂停、取消、完成和复制上周。
- 新增管理员代约和会员自助预约，校验预约窗口、容量、时间冲突、会员状态及适用卡项。
- 将预约、取消、签到和缺勤接入现有 `reserve_hold -> terminal event` 核销链路。
- 新增课次运营台，支持查看名单、代约、签到、取消和批量结课处理缺勤。
- 扩展现有账号模型，支持管理员为会员开通密码账号并在 JWT 中绑定 `memberId`。
- 将现有 Mock 团课页面改为真实周课表，并新增会员课表和“我的预约”。
- 更新功能状态矩阵、验收追踪、性能与容量验证资料。
- 首期明确不包含候补、二维码签到、消息通知、私教和报表联动。

## Capabilities

### New Capabilities
- `class-catalog`: 管理课程、教室和教练基础资料，并为排课及卡项适用范围提供稳定引用。
- `class-scheduling`: 管理真实团课课次、周课表、状态迁移和复制上周。
- `class-booking-writeoff`: 支持管理员代约、会员自助预约、取消、签到、缺勤结课以及并发安全的卡项核销。
- `member-account-binding`: 支持管理员为会员开通密码账号，并保证会员身份与资源权限绑定。

### Modified Capabilities

无。

## Impact

- 后端新增课程、教室、教练、团课课次和预约领域模型、迁移、仓储、服务及 FastAPI 路由。
- 现有认证、卡项适用课程校验、核销、审计和会员时间线服务将被复用或扩展。
- 前端替换 `/schedule` Mock 页面，新增课次运营和会员自助约课页面及对应 Nuxt BFF API。
- PostgreSQL 继续承担事务、幂等、容量和时间冲突控制，不引入 Redis 或新的调度服务。
- 测试新增契约、集成、并发、权限和端到端覆盖，并补充专项性能与容量验证入口。
