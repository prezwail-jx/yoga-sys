## ADDED Requirements

### Requirement: 管理员代约和会员自助预约
系统 MUST 支持管理员为指定会员代约以及会员预约本人，会员请求中的会员身份 MUST 从令牌获取。

管理员代约 MUST 可绕过预约开放和截止时间，但 MUST 继续校验课次状态、容量、会员状态、时间冲突和适用卡项。

#### Scenario: 会员使用有效卡项预约
- **WHEN** 已登录会员在预约窗口内预约有余位且不冲突的已发布课次
- **THEN** 系统创建 `reserved` 预约并生成关联的 `reserve_hold` 事件

#### Scenario: 管理员为会员代约
- **WHEN** 管理员选择会员并提交有效课次预约
- **THEN** 系统以管理员为操作人创建预约和预扣审计记录

### Requirement: 预约资格和时间规则
系统 MUST 校验会员状态、卡项适用范围、卡项有效性、预约窗口、容量、重复预约及同一会员时间冲突。

#### Scenario: 最后一个名额并发预约
- **WHEN** 两个请求并发争抢同一课次最后一个名额
- **THEN** 仅一个请求成功且有效预约数不超过容量

#### Scenario: 同时段重复约课
- **WHEN** 会员已有时间重叠的有效预约后预约另一课次
- **THEN** 系统拒绝新预约且不预扣权益

### Requirement: 取消预约
系统 MUST 允许会员在取消截止时间前取消本人预约，并允许管理员取消有效预约；取消 MUST 创建唯一的 `cancel_refund` 终态。

#### Scenario: 截止前取消预约
- **WHEN** 会员在取消截止时间前取消有效预约
- **THEN** 预约变为 `cancelled` 且权益按卡项快照规则处理

#### Scenario: 取消后重新预约
- **WHEN** 会员取消后在预约窗口内再次预约仍有余位的同一课次
- **THEN** 系统创建新的有效预约和独立核销链并保留原取消历史

#### Scenario: 会员逾期取消
- **WHEN** 会员在取消截止时间后请求取消
- **THEN** 系统拒绝请求且预约保持有效

### Requirement: 签到和缺勤结课
系统 MUST 允许管理员或任课教练为有效预约签到，并允许管理员完成课次时将其余有效预约批量标记缺勤。

签到 MUST 从课次开始前 30 分钟开放，并 MUST 在课次取消或完成后拒绝签到。

#### Scenario: 任课教练签到
- **WHEN** 任课教练为本课有效预约签到
- **THEN** 预约变为 `checked_in` 并创建 `checkin_commit`

#### Scenario: 管理员批量结课
- **WHEN** 管理员完成已结束课次
- **THEN** 未签到有效预约变为 `absent` 并分别创建 `absence_commit`

### Requirement: 馆方取消强制返还
系统 MUST 在馆方取消课次时强制返还所有有效预约的预扣权益，不受会员卡项取消返还规则影响；存在已签到预约时 MUST 拒绝取消课次。

#### Scenario: 馆方取消不可返还卡项的课次
- **WHEN** 管理员取消包含有效预约且卡项规则不允许会员取消返还的课次
- **THEN** 系统仍返还预扣权益并将预约与课次标记取消

### Requirement: 预约终态互斥和幂等
系统 MUST 保证签到、取消和缺勤仅能产生一个终态；预约、取消、签到、结课、取消课次、复制周和会员开户 MUST 强制使用幂等键。

#### Scenario: 重放签到请求
- **WHEN** 客户端使用相同幂等键重放相同签到请求
- **THEN** 系统返回首次结果且不重复增加已用次数

#### Scenario: 已取消预约再次签到
- **WHEN** 操作人尝试签到已取消预约
- **THEN** 系统返回冲突且不创建第二种终态

### Requirement: 预约和核销可追溯
系统 MUST 记录预约各阶段操作人、时间、结果和 trace ID，并 MUST 在会员时间线中关联预约与核销事件。

#### Scenario: 查询会员预约核销链
- **WHEN** 管理员查询完成签到或缺勤的会员时间线
- **THEN** 系统展示预约预扣及唯一终态并共享可识别的业务引用
