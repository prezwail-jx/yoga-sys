# 次卡期限、次数调整与小程序管理员后台

**时间**: 2026-08-27 19:00:04 +0800

## 变更点

1. 次数卡产品必须同时设置总次数和有效期天数；新建次数卡缺少有效期时拒绝保存，编辑没有期限的历史次数卡模板时要求补填，但不批量改写已经发出的历史会员卡。
2. 次数卡按既有开卡方式计算期限：购卡即开从购卡当天计算，首次约课开卡从首次使用当天计算。
3. 新增管理员人工调整会员卡剩余次数能力，采用正负变动值，必须填写原因，调整后余额不得小于零；不限次卡拒绝调整。
4. 所有会员卡状态均允许调整次数，包括待激活、使用中、冻结、过期和关闭。调整只改变剩余次数，不自动恢复过期或关闭状态。
5. 次数调整生成独立卡交易和审计记录，保存操作者、幂等键、调整原因、调整前后状态及次数变化；后续退款规则能识别该卡已经发生过权益变更。
6. 会员列表增加批量持卡摘要，直观展示卡名、中文状态、剩余次数和到期日，并提供卡项管理快捷入口，避免逐会员请求造成 N+1。
7. Web 管理后台增加人工调整次数表单及二次确认，同时完善次数卡有效期录入和相关中文错误提示。
8. 小程序角色体系增加管理员。正式版提供独立管理员账号密码登录入口，正式版账号密码只允许管理员使用；会员和教练继续使用微信登录，开发版和体验版保留测试账号登录。
9. 小程序新增管理员工作台和独立分包，覆盖现有 Web 管理后台能力：运营看板、会员管理、卡项办理、团课管理、私教管理、卡项产品、基础资料和统计报表。
10. 管理员可在小程序管理会员资料与账号、查看持卡摘要和业务时间线，办理购卡、续费、补卡、退款、延期、冻结、解冻和次数调整。
11. 管理员可在小程序管理团课课表、课次生命周期、预约名单、代约、取消和签到；管理私教时段、预约审批和课时记录；管理课程、教室、教练及其账号。
12. 购卡、退款、补卡、次数调整及课次取消/完成等敏感操作使用确认弹窗；次数调整必须填写原因后再次确认。
13. 清理 Web 管理后台和小程序全部用户可见英文标题、选项、状态、空状态、校验错误及提示。API 枚举值、请求字段和代码变量继续保持英文，界面统一通过中文映射展示。
14. 小程序报表支持筛选、趋势和明细查看；导出通过微信文件下载和预览能力实现，并处理下载失败和权限异常。

## 实施阶段

1. 后端卡项规则：次数卡有效期校验、次数调整 schema/service/API、交易枚举迁移、审计与契约。
2. Web 管理闭环：会员持卡摘要、快捷管理、次数调整表单、中文提示和测试。
3. 小程序认证基础：管理员角色、正式版管理员密码登录、会话恢复、路由、账号安全和管理员分包。
4. 小程序核心业务：会员管理、持卡详情、购卡及卡生命周期操作。
5. 小程序完整后台：团课、私教、产品、基础资料、账号和报表。
6. 全局中文化、回归测试、构建和真机验收。

## 验收标准

- 新建次数卡无法省略有效期，购卡或首次使用后到期日计算正确。
- 管理员可对任意状态的计次会员卡增减剩余次数，不能把余额减为负数，每次操作均可从交易和审计记录追溯。
- 会员列表无需进入详情即可识别每位会员持有哪些卡、剩余次数及到期时间。
- 正式版小程序管理员可使用后台账号密码登录，会员和教练不能绕过微信登录规则使用正式版密码入口。
- 小程序管理员可以完成 Web 后台现有主要业务，不出现仅能登录但无可用功能的空工作台。
- Web 与小程序不直接展示 `pending`、`confirmed`、`active`、`reserved` 等英文枚举，用户可见固定文案均为中文。
- 所有敏感操作有明确确认和结果反馈，重复点击不会产生重复交易。

## 假设与风险

- 已确认全部会员卡状态均允许调整次数；过期卡和关闭卡增加次数后仍保持原状态，不自动恢复可用。
- 已确认次数调整采用正负变动值并强制填写原因，不提供直接覆盖最终余额模式。
- 已确认正式版管理员使用账号密码登录，不为管理员扩展微信绑定。
- “完整后台功能”按当前 Web 管理后台菜单和真实后端接口为边界；Web 首页当前标记为模拟的数据会优先使用现有真实报表接口，不新增未定义经营指标。
- 小程序完整后台范围较大，将使用分包和共享 service/presenter 控制包体积与重复代码；微信主包和总包限制需要在构建及开发者工具中持续检查。
- 报表 Excel 预览依赖微信文件系统和 `wx.openDocument`，真机行为不能只由 Node 单元测试覆盖。
- 当前工作区存在与本需求无关的 `yoga-release-20260812.tar.gz` 及校验文件，实施过程中保持不修改、不删除、不纳入提交。
