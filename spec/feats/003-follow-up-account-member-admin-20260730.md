# 账号与会员管理后续问题记录

日期：2026-07-30

状态：待处理

来源：私教预约联调和会员账号操作过程中发现的产品/体验缺口

## 背景

私教预约和报表主流程已经接入真实后端，但在实际操作过程中发现若干账号、会员状态和错误提示相关问题。这些问题不阻塞当前私教主流程，但会影响管理员日常使用，需要后续集中处理。

## 待处理问题

### 1. 管理员无法重置会员账号密码

当前系统只保存密码哈希，无法查看会员原始密码，这是正确的安全设计。但后台也没有“重置密码”能力，导致会员忘记密码时只能通过数据库或新增功能处理。

建议方案：

1. 在后端增加管理员重置账号密码接口。
2. 支持重置会员账号和教练账号。
3. 前端在会员管理和教练资料中增加“重置密码”操作。
4. 重置后显示一次性临时密码或由管理员输入新密码。
5. 审计记录重置动作，不记录明文密码。

验收要点：

1. 管理员可以为已绑定账号的会员重置密码。
2. 非管理员请求返回 403。
3. 重置后旧密码失效，新密码可登录。
4. 审计日志包含操作者、目标账号和 trace ID。

### 2. 禁用会员无法重新启用

当前后端状态流转规则把 `disabled` 设计为终态：`disabled -> normal` 不被允许；前端也没有给禁用会员展示“重新启用”按钮。

建议方案：

1. 调整会员状态流转，允许 `disabled -> normal`。
2. 会员管理页对禁用会员显示“重新启用”按钮。
3. 重新启用后保留原会员账号、卡项、交易、核销和审计记录。
4. 增加单元测试覆盖 `disabled -> normal`。

验收要点：

1. 管理员可将禁用会员恢复为正常。
2. 恢复后的会员可以登录并预约课程。
3. 禁用期间的历史记录不丢失。
4. 非管理员无法修改会员状态。

### 3. 账号开通时用户名重复提示需要更友好

当前用户名全局唯一。重复使用已有用户名时，后端返回 `Username already exists`，但页面没有提示当前用户名已绑定给哪个资源，管理员容易误以为是当前会员已开通过账号。

建议方案：

1. 前端在账号开通表单中明确提示“用户名全局唯一”。
2. 后端保持 409，不泄露过多敏感信息。
3. 管理员可在会员列表看到“账号已开通”的状态。
4. 可选：增加账号查询/管理页，支持按用户名查找绑定资源。

验收要点：

1. 重复用户名时页面展示清晰中文错误。
2. 已绑定账号的会员按钮显示“账号已开通”。
3. 给不同会员创建账号时必须使用不同用户名。

### 4. 私教操作错误提示需要减少 Internal Server Error 暴露

已修复本轮发现的私教空闲时段、预约记录、创建时段 500 问题。但后续仍应增加端到端错误覆盖，避免后端异常直接暴露为笼统的 `Internal Server Error`。

建议方案：

1. 给私教创建时段、创建预约、确认、拒绝、取消、签到补充接口级 smoke 或集成测试。
2. 前端按 401、403、409、422、500 做更明确的中文提示。
3. 后端业务异常尽量使用 `HTTPException` 返回可理解的错误原因。

验收要点：

1. 常见业务错误展示为明确中文原因。
2. 真正 500 可通过 trace ID 在日志中定位。
3. 私教主流程 E2E 覆盖创建时段和预约状态流转。

## 优先级建议

1. P0：管理员重置密码。
2. P1：禁用会员重新启用。
3. P1：账号开通重复用户名提示优化。
4. P2：私教错误提示和集成测试增强。

## 备注

不要实现“查看原密码”。密码应继续只保存哈希，忘记密码通过管理员重置解决。

- 已支持禁用会员重新启用并保留历史数据。
- 私教前端已增加 401、403、409、422、500 中文错误映射，未知错误保留 trace ID。
- 后端聚焦单元与集成测试、前端类型检查、lint、单元测试和相关 E2E 均通过；完整 contract 套件仍受缺失历史 `group-class-booking.openapi.yaml` fixture 阻塞。
